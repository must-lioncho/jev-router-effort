# 프롬프트 기반 모델·스킬·에이전트 라우팅

날짜: 2026-10-04
요청자: Lion
구현 담당: jev-router-improver

## 사용자 의도

사용자는 스킬 이름이나 부서별 명령을 외우지 않고 자연어로 업무를 요청한다. JEV는 프롬프트와 작업 맥락을 보고 모델·reasoning effort를 선택하면서 스킬 필요 여부, 사용할 스킬, 에이전트 필요 여부와 대상을 판단한다. 담당자는 각 판단과 실행 결과를 로그로 연결해 라우팅 성능을 계산할 수 있어야 한다.

## 요청 근거와 현재 확인 범위

이 대화에서 Lion은 부서별 스킬 이름에 hr-, nss-, sut-, mpc- 같은 프리픽스를 붙이는 방식을 선택했다. 이어 사람이 매번 스킬을 지정하는 부담을 줄이도록 JEV에 선택을 맡기자고 요청했다. 마지막 요청은 모델·스킬·선택적 에이전트 라우팅을 구현하고, 입력과 판단을 기록해 성능을 평가하라는 것이다.

이것은 신규 기능 요청이다. 아직 스킬 선택 정확도나 에이전트 위임 효과를 측정하지 않았으며, 개선 성능을 주장할 근거는 없다. 저장소의 CLAUDE.md, AGENTS.md, Intend.md, DIRECTIVE.md와 docs/improvement-harness.md를 확인했다. 기존 루트 계약과 과거 이슈는 유지한다.

## 요구사항

### 선택

- 기존 모델·effort 선택, 수동 지정 존중, 맥락 유지, 체크포인트와 단일 작성자 보호를 보존한다.
- 구조화된 결과에 모델·effort, 스킬 필요 여부와 선택 목록, 에이전트 필요 여부와 선택 대상, 근거, 불확실성, 확인 필요 여부를 담는다. 각 차원은 독립적이며 스킬 없이 처리, 스킬만 사용, 에이전트만 사용, 둘 다 사용을 표현한다.
- 실제 설치·접근 가능한 스킬과 에이전트만 후보로 사용한다. 이름·설명·용도·제외 조건·소속·출처 경로·식별자·버전 또는 해시를 후보 메타데이터로 관리한다. 목록 탐색 단계에서 모든 스킬 본문을 프롬프트에 넣지 않는다.
- 부서 프리픽스는 식별 수단으로 사용한다. 현재 폴더가 HR이 아니어도 사용자가 JD 작성을 요청하면 접근 가능한 hr-make-jd를 선택할 수 있다. 폴더는 맥락이며 업무 소속을 강제하는 기준이 아니다.
- 같은 이름이 여러 출처에 있으면 경로와 식별자로 구분한다. 선택 결과만 보고 실행 대상 원문을 재확인할 수 있어야 한다.
- 명시적 스킬·에이전트 지정은 존중하고, 기존 필수 스킬 규칙과 충돌하면 숨기지 않고 보고한다. 후보가 없거나 모호하면 무선택·확인 요청·기존 처리로의 대체를 표현한다.
- 스킬 선택과 적용, 에이전트 추천과 위임을 구분한다. 지원하는 실행 경로에서는 스킬 원문과 제약을 전달하고 실제 적용 여부를 기록한다. 지원하지 않는 호스트에서는 추천에 그쳤음을 표시한다.
- 에이전트 위임은 필요할 때만 수행한다. 단순 설명은 추가 에이전트 없이 처리할 수 있다. 권한·호스트·정확한 모델 검증과 중복 위임 방지를 보존한다. 라우팅 판단은 발송·삭제·배포 권한을 추가하지 않는다.
- 현재 지원하는 CLI별 후보 검색과 스킬·에이전트 적용 방식을 조사하고, 실제 연동 범위와 미지원 범위를 명시한다. 새 글로벌 에이전트나 스킬을 만들 필요가 있으면 별도 빌드·검토 계약을 따른다.

### 로그와 성능 평가

- 요청 ID·작업 ID·대화 ID로 입력, 후보 목록, 선택 판단, 실행, 결과, 피드백을 연결한다. 연속 요청과 재시도도 구분한다.
- 로컬 비공개 로그에 시각, 입력 프롬프트 또는 재현 가능한 비공개 입력 참조, 작업 폴더·호스트·CLI, 작업 맥락, 후보 목록의 버전/해시, 라우터·정책 버전, 판단에 사용한 모델을 기록한다.
- 선택한 모델·effort·스킬·에이전트와 출처, 선택 이유의 요약, confidence, 무선택·확인 요청·대체 처리 사유, 수동 지정·변경 여부를 기록한다. 내부 사고 과정은 요구하지 않는다.
- 라우터 판단 시간, 추가 토큰·비용(측정 가능할 때), 선택과 실제 적용의 차이, 위임 수락·실제 시작·완료, 실패·오류를 별도 이벤트로 기록한다. 비용을 알 수 없으면 unknown으로 둔다.
- 비밀값을 마스킹하고 원문 입력·개인 식별자·피드백은 Git 및 배포 패키지에서 제외한다. 저장 위치, 보존 기간, 접근 범위와 삭제 방법을 문서화한다.
- 사용자·QA·실행 가능한 검증 근거로 정답 라벨과 성공·실패·unknown을 연결한다. 선택 confidence나 에이전트의 완료 선언을 성공 라벨로 사용하지 않는다.
- 모델·스킬·에이전트 차원별 선택 정확도, 필요한 대상 누락과 불필요한 선택, 무선택 정확도, 전체 작업 검증 성공률, 대체 처리·오류율, 지연·비용을 계산할 수 있는 리포트를 제공한다. 정답 라벨이 없으면 정확도는 미측정으로 표시한다.
- 각 지표의 분모·라벨 커버리지·표본 수·unknown·미지원 호스트를 표시한다. 추천 정확도와 실행 성공률을 혼합하지 않는다. 회귀 케이스와 실제 운영 측정을 구분한다.

## 검증과 완료 조건

담당자는 구현 전 directive.md에 변경 파일의 소유권과 검사 명령을 확정한다. 회귀 검사는 최소한 HR 자연어 요청, NSS/SUT/MPC 구분, 스킬 불필요 요청, 에이전트 불필요 요청, 스킬만·에이전트만·둘 다 선택, 명시적 지정, 동명 후보, 후보 없음, 모호한 요청, 이전 맥락 유지, 로그 연결·마스킹, 재시도 중복 방지, 선택/실행 불일치, 라벨 없는 성능 리포트를 다룬다.

기존 npm test와 새 회귀 검사를 실행하고, 지원하는 호스트에서 무해한 실제 라우팅·스킬 적용 smoke test를 수행한다. 실측하지 못한 동작은 미검증으로 남긴다. 구현 결과와 테스트 근거, 실제 활성화 범위, 로컬 로그·평가 명령, 커밋, 남은 작업을 이 이슈의 result.md에 기록한다. 사용자 설정 변경·프로세스 재시작이 필요하면 범위와 이유를 보고한다. 원격 push, 공개 배포, 새 스케줄 등록은 요청 범위가 아니다.
